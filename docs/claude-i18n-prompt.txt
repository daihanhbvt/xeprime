4. COOKIE-BASED LOCALE
==================================================

Persist the locale in one cookie named XP_LOCALE. Allowed values are vi and en.

Required cookie attributes:

- path: /
- sameSite: lax
- maxAge: 31536000
- httpOnly: true
- secure: process.env.NODE_ENV === 'production'

Locale resolution order:

1. Read XP_LOCALE on the server.
2. Validate it against the supported locale constants.
3. Use it when valid.
4. Fall back to vi when missing, malformed, or unsupported.

Do not use Accept-Language in this phase. A first-time visitor without a cookie must always see Vietnamese. Do not persist locale in Redux, localStorage, sessionStorage, a query parameter, the database, or a new backend preference endpoint. Cross-device synchronization is outside this task.

Create a dedicated Server Action for changing locale. It must accept only vi or en, validate input server-side, set only XP_LOCALE with the required attributes, accept no arbitrary cookie name or redirect target, and contain no open-redirect behavior.

The client switcher must start a React transition, call the Server Action, wait for success, then call router.refresh(). It must keep pathname, query parameters, URL hash, search state, and browser history unchanged. Disable repeated interaction while pending. Do not perform a full browser redirect. Do not render Vietnamese first and switch to English after hydration; initial server HTML must already match the cookie.
